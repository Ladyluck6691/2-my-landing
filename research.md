# РАЗДЕЛ 1. ТЕХНИЧЕСКОЕ ЗАДАНИЕ (СПЕЦИФИКАЦИЯ) САЙТА

## 1.1. Общие сведения о проекте

| Параметр | Значение |
|---|---|
| **Тип продукта** | Одностраничный лендинг-портфолио (one-page) |
| **Позиционирование** | Цифровой мастер полного цикла: сайты, приложения, ИИ-агенты |
| **Способ производства** | Чистый код, написанный вручную в AI-редакторе Cursor (без конструкторов и no-code платформ) |
| **Целевая аудитория** | Коммерческие клиенты: владельцы малого и среднего бизнеса, продуктовые команды, основатели стартапов |
| **Главная конверсия** | Одна целевая заявка — «Получить точную оценку проекта» |

| **Ключевое УТП** | Ручная кастомная вёрстка + разработка ИИ-агентов «под ключ» в одном исполнителе |

**Почему это выигрышная позиция.** Большинство конкурентов на рынке делятся на две группы: чистые веб-разработчики и «AI-интеграторы», которые только настраивают готовые сервисы. Комбинация «кастомная вёрстка вручную + собственные ИИ-агенты на коде» — редкая и сильная ниша, которую нужно заявить прямо в hero-заголовке.

## 1.2. Дизайн-система

### Визуальный стиль: тёмный редакционный

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#070707` | Основной фон страницы (почти чёрный, без чистого `#000000`) |
| `--bg-elevated` | `#101010` | Фон карточек и приподнятых поверхностей |
| `--fg` | `#F5F5F6` | Основной текст |
| `--fg-muted` | `rgba(245,245,246,0.6)` | Второстепенный текст, подписи |
| `--border` | `rgba(245,245,246,0.12)` | Границы карточек и разделители |
| `--accent` | `#B5FF4D` | **Единственный** неоново-кислотный акцент: кнопки, метки, активные состояния |

**Референс стиля:** сайт `karim-saab.com` — редакционный минимализм, крупная типографика, много «воздуха», выразительные эффекты вместо декоративной 3D-сферы. Подтверждённая палитра референса на Awwwards: `#222222` / `#FFFFFF` — мы адаптируем её в более глубокий тёмный вариант с одним кислотным акцентом (приём AI-студий AETHER и Orvix).

### Типографика

| Роль | Шрифт | Применение |
|---|---|---|
| **Журнальный / технический** | **IBM Plex Mono** | Метки, номера кейсов, технические подписи, навигация, служебные надписи |
| **Дисплейный (заголовки)** | Bricolage Grotesque или Space Grotesk | Заголовки секций и hero |
| **Наборный (текст)** | Manrope | Основной читаемый текст, описания, FAQ |

```css
:root {
  /* Палитра */
  --bg: #070707;
  --bg-elevated: #101010;
  --fg: #F5F5F6;
  --fg-muted: rgba(245, 245, 246, 0.6);
  --border: rgba(245, 245, 246, 0.12);
  --accent: #B5FF4D;

  /* Типографика */
  --font-display: "Bricolage Grotesque", "Space Grotesk", system-ui, sans-serif;
  --font-body: "Manrope", system-ui, sans-serif;
  --font-mono: "IBM Plex Mono", ui-monospace, monospace;

  /* Ритм и размеры */
  --space-section: 60px;          /* отступ между секциями */
  --space-block: 30px;            /* кнопки и внутренние промежутки */
  --space-tight: 15px;            /* мелкие зазоры */
  --h1: clamp(2.75rem, 8vw, 7rem);
  --h2: clamp(1.75rem, 4vw, 3rem);
  --radius: 1.25rem;
}
```

### Правила использования акцента

- Акцентный цвет — **только для интерактивных элементов и меток**: основная кнопка, активный пункт навигации, номер кейса, фокус-обводка.
- **Никогда** не окрашивать акцентом целые абзацы текста — это разрушает иерархию.
- На тёмном фоне обязательно проверять контраст: текст `--fg` на `--bg` даёт высокий контраст, а `--accent` как текст — только для крупных надписей и моно-меток.

## 1.3. Структура страницы: 7 блоков

### Блок 1. Шапка + Hero-оффер

**Задача блока:** за 5 секунд объяснить, что вы делаете, для кого и с каким результатом.

**Содержание:**
- **Шапка:** компактная строка, логотип/имя слева, 3–5 ссылок-якорей (Кейсы, Услуги, Процесс, Цены, FAQ) и основная кнопка справа.
- **Заголовок (5–12 слов), строго по формуле:**

  > **«Разрабатываю сайты, приложения и ИИ-агентов для [Ниши]»**

  Никаких абстракций вроде «Создаём цифровое будущее». Ниша подставляется конкретная — это подтверждает целевой клиент, что он попал по адресу.
- **Подзаголовок:** 1–2 предложения о результате, а не о технологиях.
- **Визуальный якорь:** **интерактивный демо-интерфейс ИИ-агента по центру** — окно чата с агентом, который отвечает на заранее заготовленные вопросы посетителя. Это заменяет абстрактную 3D-сферу и одновременно является доказательством навыка.
- **Одна CTA:** «Получить точную оценку».

```html
<section class="hero" id="hero">
  <div class="hero__demo" role="region" aria-label="Демонстрация ИИ-агента">
    <!-- Окно чата: запрос → ответ → действие. Интерактив, но не автоплей. -->
  </div>
</section>
```
```css
.hero {
  min-height: 85svh;
  display: grid;
  place-items: center;
  background: var(--bg);
  padding: var(--space-section) 1.5rem;
}
```

### Блок 2. Социальное доказательство

**Задача блока:** ответить на вопрос «насколько это надёжно и профессионально», пока нет реальных клиентов.

**Содержание:**

**Задача блока:** главное доказательство компетенции. Идёт **до** рассказа о себе.

## 1.4. Правила вёрстки

| Правило | Требование |
|---|---|
| **Правило одной кнопки** | На одном экране — **только одна** акцентная кнопка (CTA). Ссылки-якоря и текстовые ссылки не считаются CTA, но не должны конкурировать визуально. |
| **Ритм** | Крупные отступы между секциями — **около 60px** (внутренние промежутки 30px, мелкие зазоры 15px). |
| **Единство конверсии** | Формулировка основной кнопки **не меняется** по всей странице: «Получить точную оценку». |
| **Сетка** | Максимальная ширина контейнера ~1200–1280px, 12-колоночная логика, на мобильном — один столбец. |
| **Доступность** | Фокус-обводка акцентным цветом, семантический HTML, `aria-label` на интерактиве, контраст текста ≥ 4.5:1. |
| **Мобильный** | Проверка на реальном устройстве; размеры через `clamp()`, высота hero — `svh`, а не `vh`. |

## 1.5. Слой анимации (тренды 2025–2026)

Реализуется **на нативном CSS через `animation-timeline`**, без JavaScript-библиотек и без scroll-обработчиков.

### 1. Прогресс-бар чтения наверху страницы

Прогресс анимации напрямую соответствует прогрессу прокрутки: при прокрутке назад индикатор откатывается.

```css
.progress {
  position: fixed;
  inset: 0 auto auto 0;
  z-index: 100;
  width: 100%;
  height: 3px;
  background: var(--accent);
  transform-origin: left;
}

@keyframes reading-progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

@supports (animation-timeline: scroll()) {
  @media (prefers-reduced-motion: no-preference) {
    .progress {
      animation: reading-progress linear both;
      animation-timeline: scroll(root);   /* объявлять ПОСЛЕ сокращённого animation */
    }
  }
}
```

### 2. Reveal-эффект плавного проявления карточек при скролле

Базовое состояние карточек — **видимое**. Анимация добавляется только как улучшение.

```css
.reveal { opacity: 1; transform: none; }

@keyframes appear {
  from { opacity: 0; transform: translateY(16px); }
  to   { opacity: 1; transform: translateY(0); }
}

@supports (animation-timeline: view()) {
  @media (prefers-reduced-motion: no-preference) {
    .reveal {
      animation: appear linear both;
      animation-timeline: view();
      animation-range: entry 0% entry 100%;
    }
  }
}
```

### 3. Обязательные требования к анимации

- ⚠️ **Порядок объявлений критичен:** `animation-timeline` идёт **после** сокращённого `animation`, иначе сбросится в `auto`.
- ✅ **`prefers-reduced-motion` поддерживается везде** — и для прогресс-бара, и для reveal. При включённой настройке страница полностью функциональна и видима.
- ✅ **Проверка `@supports`** — при отсутствии поддержки анимация не применяется, контент остаётся читаемым.
- ✅ **Только `transform` и `opacity`** — свойства, которые композитор обрабатывает дешевле всего. Не анимировать `width`, `height`, `top`, `left`.
- ✅ **Никаких зависимостей** — слой анимации работает без GSAP, Lenis и Motion, что соответствует принципу «чистый код».

# РАЗДЕЛ 2. ЭКСПЕРТНАЯ ОЦЕНКА

> Три независимых эксперта оценивают концепцию по своим профилям: юзабилити, конверсия и восприятие реальным заказчиком. Блоки 1.1–1.6 выше считаются утверждёнными — эксперты не переписывают их, а указывают на риски и слепые зоны.

## 2.1. ЭКСПЕРТ 1 — UX-дизайнер (10 лет опыта)

### 2.1.1. Критические ошибки новичков в структуре портфолио

**1. Портфолио говорит о себе, а не о клиенте.**
Самая частая ошибка — «Мой стек», «Обо мне», «Мои навыки» на первом экране. Посетителю безразличны ваши инструменты, пока он не понял, какую проблему вы решаете. Ошибка вашей текущей структуры почти отсутствует, но Блок 2 («Стек технологий») — рискованное место: полоса логотипов сама по себе не доказательство.

**2. Кейс = картинка без истории.**
Слайд-шоу скриншотов считается плохим пользовательским опытом: рекрутеры и заказчики хотят видеть **ход мысли** и вывод, а не финальный рендер. Ваша формула «контекст → проблема → что сделали → результат» правильная. Проверка: если из карточки убрать изображение, смысл должен сохраниться.

**3. Анимация ради анимации.**
Избыточное движение — постоянная претензия к портфолио. Ваш выбор (прогресс-бар + reveal) — здоровая граница: оба эффекта **информативны**, а не декоративны. Держитесь этого принципа и не добавляйте второй слой анимации «потому что красиво».

**4. Битые и устаревшие ссылки.**
Заявка на Awwwards, где кейс ведёт в никуда, обнуляет доверие мгновенно. Для концептуальных работ — обязательно живой прототип или видео-запись взаимодействия, а не мёртвый макет.

**5. Сложно просматривать.**
Нет быстрого способа увидеть все работы и открыть нужную. У вас 6 карточек — это хорошее число, но убедитесь, что сетка сканируется за секунды: название, метка, результат — в верхней части карточки, а не после длинного абзаца.

**6. Неполная информация о специализации.**
Новички пишут «делаю сайты и всякое интересное» — заказчик не может себя квалифицировать. Три чётко названных направления (сайты / приложения / ИИ-агенты) у вас есть — сохраните эту конкретику в тексте карточек, а не только в меню.

**7. Нет ответа на «а что дальше».**
Посетитель изучил работы, но не понимает следующий шаг. Повторяющаяся CTA с одинаковой формулировкой это лечит — у вас заложено.

### 2.1.2. Что ОБЯЗАТЕЛЬНО должно быть на лендинге разработчика ИИ-агентов

| Обязательный элемент | Зачем он именно для ИИ-агентов |
|---|---|
| **Живая демонстрация агента** | Это ваш главный визуальный якорь. Пользователь должен иметь возможность **сам** задать вопрос и увидеть ответ. Главное правило: никакого автоплея, никакой обязательной регистрации, мгновенный понятный старт. |
| **Понятная граница возможностей** | Скажите прямо, что агент **умеет** и чего **не умеет**: «обрабатывает входящие заявки», «не принимает юридических решений». Ограничения повышают доверие сильнее, чем обещание всемогущества. |
| **Статус демо** | Если демо работает на тестовых данных — напишите это. Вопрос, который посетитель задаёт себе первым: «это настоящий продукт или картинка?» |
| **Время ответа** | Покажите типичную задержку и стоимость запроса. Для ИИ это ключевая практическая информация, которую конкуренты обычно скрывают. |
| **Доступность демо** | Демо должно работать с клавиатуры, иметь текстовое поле с меткой, а не только «нажмите на пример». Скринридер пользователь тоже должен понять, что это демонстрация. |
| **Технический стек блоком, а не в hero** | Стек нужен — но как подтверждение компетенции ниже по странице, после первого содержательного сообщения. |
| **Резервный путь без демо** | Если демо не загрузилось или выключен JS — пользователь всё равно должен дойти до кейсов и заявки. Демо не может быть единственным путём вперёд. |
| **Честные метрики с методом** | Рядом с 98% должно стоять, что измерялось. Иначе цифра читается как маркетинговая накрутка и обесценивает остальное. |
| **Прямой контакт без воронки** | Email или Telegram рядом с формой. Часть заказчиков не заполняет формы принципиально. |

### 2.1.3. Что раздражает посетителей и заставляет закрыть вкладку немедленно

Порядок — от самых губительных к менее критичным:

1. **Долгая загрузка.** Порог терпения измеряется секундами: заметная задержка воспринимается как поломка, а не как «мы грузим красоту». Тяжёлое демо в hero — главный риск вашего проекта.
2. **Непонятно, что это и зачем.** Если за первые секунды не считан смысл, вкладку закрывают. Это и есть обоснование вашего требования «заголовок без воды».
3. **Автоплей видео и звук.** Мгновенное раздражение и закрытие — особенно если звук нельзя немедленно выключить.
4. **Мешает читать: параллакс, дёрганье, бесконечные анимации.** Движение, которое сопротивляется прокрутке, воспринимается как поломка страницы.
5. **Тёмные паттерны:** всплывающее окно «оставьте email» через 3 секунды, фейковый счётчик «осталось 2 места», скрытая цена. Для ИИ-услуг это особенно токсично — заказчик ищет надёжного исполнителя, а видит давление.
6. **Текст-вода и общие слова.** «Инновационные решения», «команда профессионалов», «индивидуальный подход» — сигнал, что конкретики не будет.
7. **Плохая мобильная версия.** Если на телефоне текст мельче, кнопки слипаются, а демо не работает — закрывают сразу.
8. **Неочевидный следующий шаг.** Пользователь готов связаться, но не понимает, куда нажать.
9. **Лишние формы.** Каждое дополнительное обязательное поле снижает желание заполнять. Максимум — три поля, и телефон не обязателен.
10. **Отсутствие доказательств.** Ничего не показано — только обещания. Даже для концептов нужны визуальные артефакты и рабочие прототипы.

**Отдельное замечание по вашему дизайну.** Кислотный `#B5FF4D` на почти чёрном — сильное, но агрессивное сочетание. Два риска: (а) при большой площади заливки он быстро утомляет; (б) он теряет силу, если встречается везде. Соблюдайте правило: акцент живёт на кнопках, метках и фокусе — и нигде больше.

## 2.2. ЭКСПЕРТ 2 — Маркетолог по конверсии

### 2.2.1. Какой оффер железно зацепит коммерческого клиента

**Формула, которая работает: результат + срок + для кого + доказательство, что это делаете вы.**

Ваш базовый заголовок «Разрабатываю сайты, приложения и ИИ-агентов для [Ниши]» — хорошая гигиена, но он **описывает вас, а не выгоду клиента**. Коммерческий клиент не покупает «приложение» — он покупает снятую с себя задачу. Усильте его одним из способов:

| Вариант усиления | Пример формулировки |
|---|---|
| **Через результат + срок** | «Собираю ИИ-агентов, которые снимают рутину с команды — за 2 недели» |
| **Через боль и потерю** | «Ваши менеджеры тратят часы на одни и те же ответы. Я убираю это агентом» |
| **Через противопоставление** | «Кастомная разработка без конструкторов и шаблонов: сайт, приложение и ИИ-агент от одного исполнителя» |
| **Через доказательство в цифре** | «ИИ-агент, который обрабатывает 98% типовых запросов без оператора» |

**Что работает на коммерческого заказчика:**

- **Конкретика ниши.** «Для стоматологий» конвертирует лучше, чем «для бизнеса»: клиент мгновенно понимает, что вы уже решали его тип задач.
- **Срок.** Владелец бизнеса считает не деньги, а время до результата. Срок в заголовке — сильнейший фильтр внимания.
- **Снятие риска прямо в hero.** Формулировка вроде «фиксированная цена и срок в договоре» продолжает заголовок и убирает главный страх.
- **Один исполнитель, а не агентство.** Для малого бизнеса это означает отсутствие менеджеров-посредников и вменяемую цену. Это ваше настоящее преимущество — заявите его.

**Чего избегать в заголовке:** «цифровые решения», «инновационные технологии», «под ключ» без уточнения, «полный спектр услуг». Для заказчика это шум.

**Практический приём — операционализация ниши.** Если вы не готовы занять одну нишу в тексте, поставьте в hero нейтральную, но конкретную категорию («для малого и среднего бизнеса»), а внутри кейсов покажите две-три отрасли. Смешивать «для всех» и «для стоматологий» в одном заголовке нельзя — это уже противоречие.

### 2.2.2. Триггеры доверия без отзывов от крупных брендов

Отсутствие клиентских логотипов — не приговор. Доверие строится из **проверяемости**. Когда нечего показывать из социального доказательства, работают следующие шесть слоёв:

**1. Прозрачность статуса работ (самый сильный триггер для вас).**
Честная метка `CONCEPT` рядом с учебным кейсом даёт **больше** доверия, чем выдуманный клиент. Скрытая симуляция — единственное, что обнуляет сайт при обнаружении. Заказчик уважает того, кто не врёт на мелочах.

**2. Работающее демо вместо обещаний.**
Интерактивный агент в hero — ваш главный триггер доверия. Это не рассказ о навыке, а его предъявление. Оживите его так, чтобы посетитель за 20 секунд получил осмысленный ответ.

**3. Метод измерения рядом с цифрой.**
«98% точности на тестовом наборе из 200 запросов» — проверяемое утверждение. «98% точности» — рекламный тезис. Разница в восприятии огромна, а стоимость доработки — одна строка текста.

**4. Прозрачные условия работы.**
- Что входит в цену и что нет
- Сколько итераций правок включено
- Кто владеет кодом после сдачи (важно: заказчики боятся вендор-лока)
- Что происходит, если результат не устроит

Это блокирует самые частые возражения до их появления. Фактически ваш раздел «Цены и условия» — это не про деньги, а про доверие.

**5. Профессиональные артефакты вместо наград.**
Публичные репозитории, живой прототип по ссылке, чистый код, документация, схема архитектуры агента. Для технического заказчика открытый код — сильнее логотипа клиента.

**6. Личная идентификация.**
Имя, фото, локация, часовой пояс, прямой контакт. Анонимный сайт «без лица» вызывает подозрение — особенно когда речь о передаче доступа к бизнес-процессам и данных компании ИИ-агенту.

**Триггер, который стоит завести со временем:** даже один подробный отзыв «по делу» (что было сложно, что получилось) ценнее десяти коротких «всё отлично». На старте попросите обратную связь у первого заказчика **сразу после сдачи**, пока впечатление свежее, и спросите разрешение опубликовать с конкретными формулировками.

### 2.2.3. Идеальный путь посетителя (CJM): от входа до заявки

**Этап 0. Вход (0 секунд).** Посетитель пришёл из поиска, чата или рекомендации. Первое, что он оценивает — **совпадает ли обещание ссылки с тем, что он видит**. Совпадение = он остаётся. Расхождение = уход.

**Этап 1. Считывание смысла (0–5 секунд).**
Смотрит: заголовок, подзаголовок, крупный элемент справа/по центру.
Вопрос: «Это вообще про мою задачу?»
Что должно сработать: заголовок с результатом и ниша.
Провал на этом шаге: обобщённый слоган, отсутствие ниши.

**Этап 2. Проверка «в этом есть смысл» (5–20 секунд).**
Смотрит: демо-агента в hero, первые метрики.
Вопрос: «Он реально умеет то, что заявляет?»
Что должно сработать: демо отвечает на его вопрос **сейчас же**, без регистрации.
Провал: демо грузится долго, требует ввода данных, отвечает заготовленным текстом на любой запрос.

**Этап 3. Углубление в доказательства (20 секунд – 2 минуты).**
Смотрит: кейсы, цифры результата, стек.
Вопрос: «Он уже делал что-то похожее? Что получилось?»
Что должно сработать: карточка, где за 5 секунд видно проблему и результат; честная метка `CONCEPT` на учебных работах.
Провал: скриншоты без результата; все работы «идеальные» без деталей; мёртвые ссылки.

**Этап 4. Примерка на себя (2–4 минуты).**
Смотрит: услуги, процесс работы, FAQ.
Вопрос: «Сколько это будет в моём случае и что от меня потребуется?»
Что должно сработать: прозрачные шаги, понимание своей роли на каждом этапе, ответы на вопросы о правках и передаче кода.
Провал: туманный процесс, «свяжитесь, и мы обсудим» вместо объяснения.

**Этап 5. Проверка цены (4–5 минут).**
Смотрит: вилку от $995 и состав работ.
Вопрос: «Это в моём бюджете и за что конкретно?»
Что должно сработать: стартовая цена и понятный принцип оценки.
Провал: «цена по запросу» без ориентира — часть аудитории уходит, не написав.

**Этап 6. Снятие последних сомнений (5–6 минут).**
Смотрит: FAQ.
Вопрос: «А если мне что-то не понравится?»
Что должно сработать: 4–5 честных ответов, включая неудобные темы (правки, сроки, ответственность).
Провал: FAQ из отговорок или его отсутствие.

**Этап 7. Действие (6–7 минут).**
Смотрит: финальный блок и форму.
Вопрос: «Что мне нажать?»
Что должно сработать: та же кнопка «Получить точную оценку», 2–3 поля, ясное обещание, что произойдёт дальше («отвечу в течение 24 часов»).
Провал: длинная форма, скрытое поле телефона, отсутствие обещания по времени ответа.

**Этап 8. Подтверждение (после отправки).**
Ожидание: письмо/сообщение «заявка получена, отвечу тогда-то».
Провал: тишина после отправки — самый частый разрыв воронки у фрилансеров, и он обесценивает весь предыдущий путь.

**Ключевая метрика пути.** На каждом этапе возможно ровно **одно** основное действие. Если посетителю в один момент предлагают и «смотреть работы», и «заказать звонок», и «скачать прайс» — часть аудитории парализует выбор. Ваше «правило одной кнопки» из спецификации снимает именно этот риск.

**Где именно теряется конверсия в вашей текущей структуре:**

| Точка риска | Проблема | Решение |
|---|---|---|
| Блок 2 (соц. доказательство) | Полоса логотипов и стек в начале — слабое доказательство без клиентов | Сместить акцент на цифру с методом и на рабочие прототипы; стек оставить как одну строку |
| Блок 3 (кейсы) | Учебные работы без пометки читаются как обман | Обязательная метка `CONCEPT` + живая ссылка на прототип |
| Блок 5 (цены) | «От $995» без объяснения состава — подозрительно низко | Показать, что входит в стартовый пакет, и от чего растёт цена |
| Весь путь | Нет обещания по времени ответа | Добавить «отвечаю в течение 24 часов» у формы |

## 2.3. ЭКСПЕРТ 3 — Потенциальный клиент (владелец бизнеса)

> Прямая речь заказчика: «Я не разбираюсь в React и не буду разбираться. У меня есть проблема, мало времени и ограниченный бюджет. Я решаю за минуту, стоит ли тратить на вас вечер».

### 2.3.1. На что я смотрю в первые 5 секунд

1. **Понял ли я, чем этот человек может быть мне полезен.** Если заголовок про «цифровые решения», я не понимаю, ко мне это или нет. Мне нужна фраза вида «делаю ИИ-агентов, которые отвечают клиентам вместо менеджера» — тогда я сразу думаю: «а у меня как раз менеджеры тонут в переписке».
2. **Внушает ли сайт доверие как витрина.** Если сайт разработчика сделан криво — для меня это приговор. Вы продаёте сайты, и ваш сайт — ваш главный образец работы. Кривая вёрстка здесь убивает доверие быстрее любого текста.
3. **Сколько это стоит и какой порядок цен.** Мне нужно понять за 5 секунд, это «$500», «$5000» или «$50000». Если цены спрятаны, я предполагаю худшее и ухожу, потому что не люблю тратить время на звонок, где мне назовут цифру вне моего бюджета.
4. **Есть ли что-то живое, что можно потрогать.** Если в центре экрана реально работает окно агента — я сразу вижу, что человек умеет, а не рассказывает. Это единственное, что заставит меня задержаться.
5. **Не выглядит ли всё это нарисованным для красоты.** «Идеальный» сайт с несуществующими клиентами вызывает у меня подозрение быстрее, чем скромный сайт с честными работами.

**Вывод по 5 секундам:** я ищу три ответа — *что мне это даёт*, *сколько стоит*, *можно ли этому человеку верить*. Если хотя бы один ответ не находится, я закрываю вкладку.

### 2.3.2. Что заставит меня остаться и изучать сайт дальше

| Что сработает | Почему это работает именно на меня |
|---|---|
| **Живой работающий агент** | Я могу сам написать ему фразу и увидеть, что он отвечает осмысленно. Это заменяет десять страниц описаний. |
| **Цифры с пояснением** | «Обрабатывает 98% типовых запросов» — я представляю, сколько денег сэкономлю. Но если не написано, откуда цифра, я решаю, что она выдумана. |
| **Конкретный пример «было/стало»** | «Раньше менеджер тратил 3 часа в день на одни и те же ответы, теперь агент отвечает сам» — я мгновенно примеряю это на свой бизнес. |
| **Честность про концепты** | Если человек пишет «это учебный проект, вот что я в нём сделал», я думаю: «значит, и в работе он не будет мне вешать лапшу». Это неожиданно сильно повышает доверие. |
| **Срок и цена** | Понятный срок и понятная вилка цены дают мне ощущение контроля. Я знаю, на что подписываюсь. |
| **Понятный процесс из шагов** | Я боюсь не результата, а процесса: бесконечных правок, пропавшего исполнителя, непонятных сроков. Прозрачные шаги снимают этот страх. |
| **Прямой контакт и живой человек** | Имя, лицо, Telegram, часовой пояс. Я должен понимать, что за сайтом стоит реальный человек, который отвечает. |

**Что заставило бы меня остаться дольше всего:** если в кейсах есть **разбор процесса**, а не только результат. Мне интересно, как человек думает — потому что именно способность решать проблемы мне и нужна, а не готовая картинка.

### 2.3.3. Что покажется подозрительным и заставит закрыть вкладку

1. **Скрытые цены и «узнайте стоимость по запросу».** Моё первое предположение — «дорого, не по моим деньгам». Круг замкнулся, я ухожу.
2. **Выдуманные или размытые отзывы.** «Отличный специалист, рекомендую!» без имени, компании и конкретики — значит, скорее всего, сочинил сам. Один подробный отзыв с деталями весомее двадцати общих.
3. **Слишком много обещаний и «всё под ключ».** Если человек делает всё — сайты, приложения, ИИ, рекламу, дизайн и ещё немного — я не верю, что он делает это хорошо. Лучше три честные компетенции, чем десять заявленных.
4. **Термины без перевода.** «Интегрируем LLM-пайплайны и RAG-архитектуры» — я не понимаю и чувствую себя глупо. Правильно: сначала по-русски, что это даёт мне, потом при желании термин в скобках.
5. **Непонятная польза от ИИ.** Половина сайтов про ИИ пишут об ИИ. Мне нужно не «мы используем GPT-4», а «агент отвечает клиентам круглосуточно, и вы экономите на зарплате оператора». Если выгода не сформулирована через мои деньги и моё время — я не вижу смысла.
6. **Агрессивное давление.** Всплывающие окна, «осталось 2 места», «запишитесь сейчас» — я чувствую, что мне что-то продают, и закрываю. Особенно когда речь о деньгах за незнакомый мне продукт.
7. **Ощущение «сайт-визитка ради красоты».** Если сайт только про самого автора и его творчество, без ответа на «что мне это даст» — я считаю, что передо мной художник, а не подрядчик.
8. **Отсутствие информации о передаче результата.** Ключевой мой вопрос: **кому будет принадлежать код и данные?** Если об этом ни слова, у меня закрадывается мысль о вендор-локе, и я не подписываюсь.
9. **Непонятно, кто отвечает.** Анонимный сайт без имени и лица. Мне нужно передать человеку доступ к бизнес-процессам и данным клиентов — я не доверю это «студии» без лица.
10. **Тяжёлый, тормозящий сайт.** Если ваш сайт грузится долго, у меня один вывод: «свой сайт не оптимизировал — мой будет таким же».

**Отдельно: что меня раздражает в ИИ-сайтах.** Меня не интересуют технологии. Меня интересует, сколько заявок агент закроет, сколько часов рутины снимет и сколько мне это сэкономит. Если сайт говорит только о технологиях, я остаюсь в недоумении, зачем мне это.

## ✅ Что в вашей концепции уже сделано правильно

Эксперты отдельно подтверждают сильные решения — их стоит сохранить без изменений:

- **Формула кейса** «контекст → проблема → что сделали → результат» — решает главную ошибку новичков.
- **7-блочная структура** соответствует проверенной последовательности продающего лендинга.
- **Одна CTA на экран и одна формулировка кнопки** по всей странице — снимает паралич выбора.
- **Нативная анимация только из двух эффектов** — прогресс-бар и reveal. Это информативные, а не декоративные эффекты; принцип «анимация должна служить цели» соблюдён.
- **Поддержка `prefers-reduced-motion`** для обоих эффектов — закрывает и доступность, и раздражение от движения.
- **Прозрачный процесс из 5 шагов** — снимает главный страх заказчика.
- **Честная фиксация статуса учебных работ** — превращает слабость в преимущество доверия.

## 📌 Три вывода, если сократить всё до одного абзаца

1. **Продавайте результат, а не технологию.** Заказчику всё равно, на чём вы пишете. Ему важно, сколько часов и денег это сэкономит.
2. **Ваш сайт — это ваш первый кейс.** Если он грузится медленно или выглядит криво, никакие тексты не спасут.
3. **Честность о концептах — ваше конкурентное преимущество, а не недостаток.** На старте без клиентов правда работает лучше, чем имитация.
